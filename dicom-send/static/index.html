Destinations

The folder is sent to each enabled destination one after another, never in parallel - sending to several at once would multiply exactly the load this screen is trying to limit. Test sends a C-ECHO so you can confirm a target is up before committing to a long send.

Pacing

Off, the whole folder goes to one DcmSnd process and leaves as fast as the link allows - that burst is what backs the downstream up. On, the folder is split into series (each subfolder holding files) and sent one series at a time with a random gap in between. Random rather than fixed so the traffic never settles into a lockstep rhythm.

Health checks and retry

Liveness is measured with a DICOM C-ECHO to the same AET/host/port you're sending to - if the target answers an echo it is accepting associations.

A failed series is retried only after an echo succeeds, with a growing backoff - so a struggling receiver isn't met with an immediate retry storm.
